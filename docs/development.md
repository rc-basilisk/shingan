# Developing shingan

## Layout

shingan is a Cargo workspace:

| Crate | What it contains |
|---|---|
| `shingan-core` | File discovery, the `Detector` trait and the five detectors, MinHash, LSH grouping, the scan orchestrator (`DuplicateScanner`) |
| `shingan-db` | SQLite persistence: scan sessions, groups, the signature cache (`impl SignatureCache for Database`) |
| `shingan-ml` | Image classification: heuristics, CLIP via ONNX Runtime, cloud providers, model and runtime downloads |
| `shingan-utils` | Shared by both front ends: auto-sorter with undo journals, safe cleanup (trash, keep strategies), persisted settings |
| `shingan-cli` | The `shingan` binary |
| `shingan-gui` | The `shingan-gui` binary (Iced 0.13) |

Dependency direction: `core ← db`, `core ← ml ← utils ← {cli, gui}`.

Other folders: `tools/` (the CLIP prototype generator), `docs/`, `assets/`.

## Building and testing

```sh
cargo build                       # debug build of everything
cargo test --workspace            # unit + integration tests
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all
```

CI runs formatting, clippy and tests on every push to `main` and every pull
request (`.github/workflows/ci.yml`). It uses the latest stable Rust, so new
clippy lints can appear without code changes. The minimum supported Rust
version is 1.88 (set by dependencies).

Linux needs the GUI build dependencies:
`pkg-config libxkbcommon-dev libwayland-dev libgl-dev libegl-dev libdbus-1-dev`
(plus `libxcb*-dev` on some distributions).

### Tests that need real models

Two ignored tests exercise the real CLIP model and ONNX Runtime:

```sh
SHINGAN_MODEL_DIR=~/.local/share/shingan/models SHINGAN_SAMPLES=./some-images \
  cargo test -p shingan-ml --test clip_live -- --ignored --nocapture
```

`classify_samples` prints the top 3 categories for every image in the samples
folder. `missing_runtime_is_an_error` checks that a missing runtime is
reported instead of crashing (run it with `ORT_DYLIB_PATH=/nonexistent`).

### Regenerating the CLIP prototypes

```sh
pip install onnxruntime tokenizers numpy
# download onnx/text_model.onnx and tokenizer.json from
# https://huggingface.co/Xenova/clip-vit-base-patch32 into MODEL_DIR
python tools/gen_clip_prototypes.py MODEL_DIR
```

Edit the `PROMPTS` table in the script to change how categories are described.
The order must match `ImageSubCategory::ALL`.

## Adding a detector

Implement `shingan_core::detector::Detector`:

- `compute_signature`: a string fingerprint, or `None` if the file can't be read.
- `compare_signatures`: similarity in `0.0..=1.0`.
- `candidate_keys`: LSH keys. Any pair at or above the threshold **must**
  share a key. Return one constant key to compare everything.
- `prepare` (optional): parse signatures once for fast comparison.
- `exact_only` (optional): `true` lets the scanner skip files with unique sizes.

If you change a signature format, bump the detector's version tag (as
`ImageDetector` and `minhash` do) and `shingan_db::schema::SCHEMA_VERSION` with
a migration that clears `signature_cache`.

## Releasing

Releases are built by [cargo-dist](https://github.com/axodotdev/cargo-dist)
(`dist-workspace.toml`, `.github/workflows/release.yml`):

1. Update `CHANGELOG.md`. The section for the new version becomes the release notes.
2. Bump `version` in the root `Cargo.toml` (all crates share it) and commit.
3. Tag and push: `git tag v0.3.0 && git push origin v0.3.0`.

The workflow builds the CLI and the GUI for Windows x64, macOS arm64 and Linux
x64, and publishes archives, shell/PowerShell installers and checksums to a
GitHub release. `release.yml` is generated by `dist init` and is checked in
with `allow-dirty = ["ci"]`, so re-run `dist init` after upgrading cargo-dist
and re-apply any local edits.
